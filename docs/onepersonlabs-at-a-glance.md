# OnePersonLabs at a glance

OnePersonLabs helps you direct Codex from a defined problem to a checked,
delivered change. You choose the outcome and its limits; Codex uses the relevant
skills, tools, and project instructions. GitHub records actionable status when
it is the selected tracker.

The detailed explanations and diagrams now ship with the plugin. The sections
below retain the original entry points for existing links.

## Follow one issue through delivery

The [workflow guide](../plugins/onepersonlabs/docs/workflow.md) follows a file-export
bug from setup and acceptance through checks, review repair, and delivery.
It includes prompts for starting, reporting blockers, resuming, and finishing.

## Stop a repair loop before it becomes the project

The [workflow guide](../plugins/onepersonlabs/docs/workflow.md) explains the bounded
work agreement and reconsideration rule. Failed hypotheses and cumulative costs
stay with the same observable problem across agents and resumptions.

## Choose how changes reach the base

The [delivery lanes](../plugins/onepersonlabs/docs/workflow.md) cover serial work
on the selected branch, isolated worktrees with local integration, and opt-in
PR delivery. Worktrees do not require PRs; existing protections still apply.

## Count owners separately from helpers

The [workflow guide](../plugins/onepersonlabs/docs/workflow.md) distinguishes the
primary issue owner from optional bounded helpers and explains aggregate budgets.

## Know which copy changed

[Configuration and hooks](../plugins/onepersonlabs/docs/configuration-and-hooks.md)
and [contributing](contributing.md#publish-and-refresh) distinguish source,
publication, installation, and fresh-session loading.
For interrupted work and retained human input, use
[collaboration and recovery](../plugins/onepersonlabs/docs/collaboration-and-recovery.md).
