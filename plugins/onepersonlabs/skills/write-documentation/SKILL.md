# Write useful product documentation

Apply the shared drafting foundation in the applicable OnePersonLabs AGENTS.md.
Read [the documentation workflow](references/documentation.md) before creating
documentation or changing its behavior claims or reader journey. A wording-only
edit preserves applicable evidence; inspect the changed sentence in context
without restarting the complete product investigation.

For requirements, procedures or technical explanations, also use
$onepersonlabs:write-technical and its applicable precision rules. Preserve
the document's intended reader and voice. Developer-facing commentary follows
that skill's response guidance; it does not determine the document's voice.

Own the full reader journey: establish the starting point, verify the affected
behavior, write the shortest complete path and check its result. Update related
entry pages and examples when changed claims affect them. A source review does
not establish runtime success or human comprehension. Use current sources and
existing checks proportionately; retain unresolved facts as unresolved.

Application controls use $onepersonlabs:write-ui. General correspondence and
editorial prose use $onepersonlabs:write. Route by the section's purpose rather
than its filename or the word "rewrite". Do not run a general prose scanner for
every documentation edit; use it when a prose-style audit is requested.
