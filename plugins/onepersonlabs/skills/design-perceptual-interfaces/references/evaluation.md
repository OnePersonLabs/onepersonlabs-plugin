# Compare, judge, and retain corrections

Keep three evidence channels separate:

| Channel | Useful evidence | Does not establish it |
| --- | --- | --- |
| Semantic correctness | Source and runtime invariants; truthful states and actions | An attractive screenshot |
| Comprehension and control | Unbriefed interpretation, actions, errors, recovery | Agent agreement or a passing test |
| Aesthetic experience | Actual preference comparisons and specific corrections | Absence of known clichés |

Use [interpretation testing](validation.md) for meaningful distinctions. Ask what
changed, what stayed the same, what can happen next, and what the system knows.
Ask preference separately. Preserve response wording, participant context, and
sample limits. Do not teach the answer immediately before asking it.

## Evaluate the capability

When an effectiveness comparison is authorized, keep the same task, inputs,
time/compute budget, and acceptance constraints across conditions:

- A: ordinary coding agent.
- B: [the recovered earlier skill](legacy-method.md) and its two references.
- C: the current meaning, specimen, and observation loop.
- D: C plus image-generated visual hypotheses and extracted grammar.

Use multiple samples when the budget supports them. Record model, effort, source,
generation cost, review cost, and missing observations. Hide condition labels
and randomize presentation before judgment. Do not call handcrafted good/bad
specimens A or B. They test the apparatus, not model effectiveness.

The comparison tool creates a self-contained image gallery and a separate private
mapping. Use neutral captions; check the pixels for revealing labels. Keep the
mapping away from the reviewer until judgments are recorded. Gallery order is
randomized once and persisted. It is not proof of an independent or blind judge
when the judge already knows the candidates.

Do not invent a universal design score. If the proposed loop does not produce
useful decisions or a visible preferred difference, identify the stage that added
no information and remove or replace it. Do not respond by adding more doctrine.
Do not start a recurring benchmark or AI invocation suite as part of normal use.

## Contextual episodes

Store a meaningful correction in the project's current design evidence location.
An episode includes problem, context, alternatives, selected and rejected reasons,
judgment actor and basis, evidence pointers, confidence, and applicability limits.
The [workbench](workbench.md) validates and retrieves these plain JSON records.
It owns no global preference database or task lifecycle.

User statements need their actual source. A model inference is a model inference.
Keep a provisional autonomous choice distinct from the user's selection. Preserve
mixed choices, such as one candidate's grouping and another's relation treatment,
as a named composed alternative with reasons and source pointers.

Retrieve by the communication problem and compatible context. The helper uses
explicit exact context fields; the agent assesses relevance and limits. A missing
match is a reason to design from present evidence, not infer a universal preference.
After an actual later use, record how the prior correction changed that decision
in the existing task evidence. Do not create learning ceremony for trivial edits.
